# 产能公告数量表达的上下文采集

采购部在整理供方产能公告，同一页上有“1.2亿元”“不少于三百万”和“单位：万吨”。本仓库在本地模拟源之上提供两类能力：原始资料预览（保留）与有来源依据的数量表达接收。

## 当前能力

`npm run demo` 从本地资料源读取一次，做两件事并追加写入 `var/captures.json`：

1. 原始预览（既有行为，只剥标签，不识别数量）。
2. 数量表达接收：解析公告 HTML 的章节、单位声明、表格与跨栏脚注，接收数量表达并保留解释链。

接收原则：

- 区分确数、区间、约数、上下界与明确的未知（如“待定”）；缺失值不写成 0。
- 单位可来自数量紧邻的局部单位、章节或全文的“单位：X”声明；局部优先，覆盖关系写入证据，可解释它覆盖了哪里。
- 统计口径可来自表头、行标签与脚注；两种解释同样合理（如行标签“主产品”与脚注“含副产品”冲突、同一范围多个单位声明）时保留候选待核，不按行业常识取舍。
- 型号、编号、日期中的数字不接收为数量，并登记排除原因；两个看起来相同的数（如投资 1.2亿 与产能 1.2～1.5）按统计对象分别接收。
- 中文大数与阿拉伯数字按精确十进制解析（三百万=3000000，1.2亿=120000000），只使用已登记的十进制单位换算，未登记单位不猜测。
- 每条接收记录携带规则版本（`src/quantity/rules.mjs` 的 `RULE_VERSION`）。换清洗规则后重新接收只追加新记录，历史解释保留可查，不静默改写。

`npm run explain -- <编号>` 面向业务人员解释某条数量表达：原文片段、上下文依据、保留的表达语义、标准化值、待核原因与候选，以及该片段在不同规则版本下的历史解释。不带参数时列出最近一次接收的全部编号与未接收为非数量的排除项。

## 运行

固定 Node.js 22.22.1，不依赖外部服务。所有 HTTP 资料源由进程在回环随机端口启动并关闭。

```sh
npm ci
npm run build
npm test
npm run demo
npm run explain
```

推荐使用固定镜像构建，首次构建会安装锁文件中的依赖；运行时不需联网。

```sh
docker build -t plant-quantity-context .
docker run --rm --network none --ipc=host plant-quantity-context npm test
docker run --rm --network none --ipc=host plant-quantity-context npm run demo
```

开发时 `npm start` 打印本地源地址；设置 `PORT` 可指定监听端口，未设置时自动分配回环端口。浏览器页面或 HTTP 接口可直接查看。`CAPTURE_PATH` 可改变接收文件路径。重复运行演示追加记录；删除 `var` 可从空接收状态开始。

## 模块

- `src/source.mjs`：该业务的本地资料源与演示控制，独立于接收行为，不替接收器完成核对。
- `src/domain.mjs`：现有原始资料预览和领域数据结构。
- `src/preview.mjs`：演示入口，先保留原始预览，再执行一次数量表达接收。
- `src/collect.mjs`：公告采集运行器：取文档、调用提取、追加接收记录。
- `src/quantity/`：数量表达接收。`html.mjs` 标签树、`context.mjs` 章节/声明作用域、`number.mjs` 中文数字与精确十进制、`units.mjs` 单位登记与换算、`extract.mjs` 提取与候选保留、`explain.mjs` 解释渲染、`rules.mjs` 规则版本。
- `src/explain.mjs`：业务查询入口（解释与历史）。
- `src/store.mjs`：带完整性校验的单进程顺序接收文件，不是跨进程事务数据库。
- `fixtures/source.json` 与 `fixtures/controls.json`：本地供方资料及可切换情形。
- `docs/source.md`：接口和来源约定。
- `test`：预览、源端边界、接收文件完整性与数量表达接收测试。

## 业务核对

以下情况均可被独立观察，由 `test/quantity.test.mjs` 覆盖：

- 区间上下界和约数不当确数。
- 章节单位与局部覆盖（覆盖关系写入证据并可解释）。
- 型号及日期不误认数量（登记排除原因）。
- 冲突口径保留多候选（行标签对脚注；同范围多单位声明）。
- 明确的未知（“待定”“统计期未说明”）不记为 0。
- 解释变更不静默覆盖原记录（规则版本加追加式接收文件）。

## 短时操作演示

从空 `var` 运行 `npm run demo`，查看本次接收的数量表达分类、待核项与原因；再运行 `npm run explain -- <编号>` 查看某条的解释链；`npm test` 查看本地源边界、接收文件检查与数量接收行为。固定环境中的这几步应在 90 秒内完成。演示展示实际完成情况与未确认部分及原因，不回放旧日志，不以源端控制操作代替接收结果。
